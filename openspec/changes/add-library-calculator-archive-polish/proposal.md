## 为什么改

**使用者的原话**：「和 Days Matter 对比，页面太简陋了，不好看。缺少如下功能：1、按类型区分 2、原版有事件库 3、原版配色好看 4、原版有日期计算器 5、原版有归档功能」

首版把「天数算对」这件事做完了，但停在了能用、不好看的阶段。装到手机上跟 Days Matter 并排一比，差距全在体验层。

**逐条对账**：

| # | 使用者说的 | 首版实际状态 |
|---|---|---|
| 1 | 按类型区分 | **已实现**（分类单选 + 三个默认分类）。但只在编辑页里，列表页看不出分类，观感上等于没有 |
| 2 | 事件库 | **没有**。每个事件都要手打标题，连春节都要自己输 |
| 3 | 配色好看 | **没有**。Material3 默认色，白底黑字，卡片无背景 |
| 4 | 日期计算器 | **没有** |
| 5 | 归档 | **没有**。过期事件只能删，删了就没了 |

**判断**：这些不是「锦上添花」。事件库解决的是**记录成本**（铁律三：三步以内），
归档解决的是**数据不敢删**，配色解决的是**愿意每天打开看一眼**——
一个倒数日 App 如果不好看， reminding 的价值就归零。

## 做什么

1. **事件库**（`specs/event-library/`）：内置节日与热门倒数日，一键添加
2. **日期计算器**（`specs/date-calculator/`）：两日期间隔 + 日期前后推算
3. **归档**（`specs/archive/`）：归档而非删除，可恢复
4. **视觉重做**（`specs/visual-design/`）：分类主题色 + 卡片渐变 + 排版层级

## 不做什么

- **不做云同步** —— 数据不出设备（铁律二）
- **不做桌面小组件** —— 仍单开 change，Glance 用错会运行时崩溃
- **不做自定义背景图** —— 需要相册权限，与「数据是你的」冲突；用渐变色替代
- **不做周规则类节日**（母亲节「5 月第 2 个周日」等）—— 需要新的重复规则类型，成本与收益不匹配

## 验收标准

1. 从事件库添加春节，三步内完成，且每年自动按农历正月初一重复
2. 日期计算器算 2026-01-01 到 2026-12-31 得 364 天
3. 归档一个事件，主列表消失，归档页能看到并一键恢复，数据不丢
4. 三个默认分类各有一种主题色，列表页能一眼看出分类归属
